# Contexts replace Working Hours, and every Task is placed only in its own Context

dynacal used to have one set of Working Hours that every Task could use. The owner wants to plan their day around Contexts, in the spirit of Cal Newport's Eudaimonia Machine: named weekly windows such as "Deep work: weekdays 08:00–11:00", with certain Tasks done only in certain windows. We considered keeping Working Hours and adding Contexts as a narrower limit on some Tasks, with Tasks outside any Context free to fill a Context's windows. We chose instead to drop Working Hours as a separate idea: every Task belongs to exactly one Context (the Default Context unless the owner picks another), and is placed only inside that Context's windows. A Context's time is reserved for its own Tasks, except where the owner makes windows of different Contexts overlap. We chose this because two overlapping ideas (Working Hours and Contexts) would confuse more than they help, and because the owner wants the strict version: a deep-work window shouldn't fill up with shallow Tasks. The owner's old Working Hours became the Default Context. Don't bring back a separate Working Hours setting, or let a Task spill into another Context's time to avoid being At Risk; overlapping windows are the way to share time.
